# HerbAlly — Fresh Deep+Wide Audit v2 (2026-06-22)

A broader, deeper re-audit than the prior run. 8 parallel reviewers covered: DB/RLS, API routes + server actions, AI/external APIs, Stripe/donations, Next.js 16 App Router, business logic, frontend, and infra/i18n/SEO/tests. Each reviewer read whole files (not just grep), cited `file:line` evidence, re-verified the just-landed PR #44 fixes, and assigned severity + confidence.

**Headline:** 3 Critical, 2 High, 18 Medium, 26 Low. The prior PR #44 fixes are mostly sound, but this audit surfaced **3 new Critical issues the prior audit missed** — two of them on patient-safety paths.

## Critical (3)

### C1 — `herb_monographs` runs in production WITHOUT Row Level Security

- **Location:** `supabase/migrations/00019_create_monographs_table.sql` (no `ENABLE ROW LEVEL SECURITY`); fix at `supabase/migrations/00042_herb_monographs_rls.sql` (pending PR #44)
- **Evidence:** 00019 creates `herb_monographs` (with `drug_interactions`, `safety_notes`, `pregnancy_category`, `key_citations`) and never enables RLS. The 00042 comment confirms: _"created in 00019 without ENABLE ROW LEVEL SECURITY and zero policies."_ With RLS off, Supabase's default grants give `anon`/`authenticated` full DML.
- **Why it matters (patient safety):** Anyone with the public anon key (embedded in the browser bundle) can `SELECT` draft/unpublished monographs and **modify `drug_interactions` / `safety_notes` / `pregnancy_category` on any monograph** — injecting medical misinformation the app surfaces to end users — or delete monographs outright. On a medical SaaS this is a medical-misinformation injection vector.
- **Fix:** Ship PR #44 so 00042 lands. 00042 is correct (SELECT on `status='published'`; admin `EXISTS`-gated DML; WITH CHECK present on INSERT/UPDATE). **The risk is the delay, not the fix.**
- **Confidence:** 1.0 · _(Prior audit filed this as C-1; re-listed because it is still live in prod.)_

### C2 — `saveHealthProfile` upsert is broken: no UNIQUE constraint on `health_profiles.user_id`

- **Location:** `src/lib/actions/profile.ts:191-203`; schema `supabase/migrations/00034_health_profiles_and_ratings.sql:2-14`
- **Evidence:** The M-6 fix calls `upsert({ conditions, allergies, user_id }, { onConflict: "user_id" })`. But the only constraint on `health_profiles.user_id` is a **non-unique** index (`idx_health_profiles_user`, 00034:14). No migration (00034/00038/00045) adds a UNIQUE constraint. PostgreSQL `ON CONFLICT (user_id)` requires a unique/exclusion constraint — without one it raises _“there is no unique or exclusion constraint matching the ON CONFLICT specification.”_
- **Why it matters (patient safety):** The health-profile save is the gateway for conditions/allergies that drive personalized safety warnings. If the upsert errors, **every “add condition / add allergy” returns `{success:false}`** and the UI toasts “Failed to save health profile.” A user who enters a serious allergy (e.g. ragweed) sees an error, reloads, finds it gone — and later gets an allergenic herb recommendation because the allergy was never persisted. Alternatively, if PostgREST falls back to a plain INSERT, duplicate rows accumulate and `getHealthProfile`’s `.maybeSingle()` errors with “JSON represents multiple rows,” breaking the profile page entirely.
- **Fix:** Add a partial unique index in a migration:
  ```sql
  CREATE UNIQUE INDEX IF NOT EXISTS idx_health_profiles_user_unique
    ON public.health_profiles(user_id) WHERE user_id IS NOT NULL;
  ```
  Verify no duplicate `user_id` rows already exist in prod before applying.
- **Confidence:** 0.85 · **NEW — the prior audit missed this; the M-6 fix is subtly broken.**

### C3 — Live streamed AI output has NO server-side medical safety guard; client guard is post-stream and bypassable

- **Location:** `src/app/api/chat/route.ts:363-414` (stream pump); `src/lib/chat/safety-guard.ts:201`; `src/components/pharmacist/chat-interface.tsx:312-331`
- **Evidence:** The server stream pump does `fullContent += content; controller.enqueue(...)` with **no** call to `evaluateAssistantContent`. `guardResponse` is invoked only (a) inside `persistToCache` (line 46, only when `servedModel === primaryModel`, only after stream end) and (b) the cache-HIT path (line 249). The client accumulates `fullContent` and calls `setStreamingContent(fullContent)` on every chunk — **displaying raw model output to the user in real time** — and only evaluates the guard after `done`, then swaps in `finalContent`. The user has already seen the dangerous text during streaming.
- **Why it matters (patient safety):** This is a health product. A model emitting “stop taking your insulin” or a megadose instruction streams straight to the user’s screen unfiltered. The client guard is (1) after-the-fact — the harm is visual exposure, (2) trivially bypassable by any client that doesn’t run it (curl, modified client, proxy). The server is the only trustworthy enforcement point and it does not enforce on live output.
- **Fix:** Buffer the full response server-side before sending (sacrifices streaming) **OR** run a streaming regex guard on each accumulated chunk and (i) abort + replace with a refusal on a hard-block match, (ii) suppress further chunks. At minimum, for **fallback models** (which cannot be cached/guarded post-hoc) buffer-then-guard is the only safe option — free Llama models are the highest unsafe-output risk.
- **Confidence:** 0.95 · **NEW — the prior audit noted the caching gap but missed that live output is unguarded.**

## High (2)

### H1 — `checkUserMedicationInteractions` is dead code — the medication-safety feature is not wired into any UI

- **Location:** `src/lib/actions/profile.ts:374-452` (defined); grep of `src/components/` and `src/app/` finds **zero callers**
- **Evidence:** Commit `567796c` described it as “Ready for integration into herb detail pages.” The herb detail page (`src/app/(main)/herbs/[slug]/page.tsx`) renders the static `interactions` table but never calls `checkUserMedicationInteractions`. No component imports it.
- **Why it matters (patient safety):** A user who enters “Warfarin” into the medication tracker, then browses St. John’s Wort, sees only the generic interactions table — no personalized flag that _their_ warfarin conflicts with this herb. The tracker gives a false sense of safety. For users on anticoagulants, SSRIs, oral contraceptives (the exact drugs seeded in `00016_seed_interactions.sql`), an unwarned interaction can be life-threatening (serotonin syndrome, bleeding, unplanned pregnancy).
- **Fix:** Call `checkUserMedicationInteractions(herb.slug)` from the herb detail page server component and render a `SafetyAlert` at the top of the page when `matched.length > 0`. The `SafetyAlert` component (`src/components/herbs/safety-alert.tsx`) already supports `interactionCount`.
- **Confidence:** 0.95 · **NEW — prior audit did not catch that the feature was unwired.**

### H2 — Fallback-model AI output is neither cached nor ever server-side guarded

- **Location:** `src/app/api/chat/route.ts:265, 373, 388`
- **Evidence:** `persistToCache` calls are gated on `servedModel === primaryModel` (lines 373, 388); the comment at 264 says fallback (free) models can emit low-quality output. But `guardResponse` is only ever called inside `persistToCache` — so **fallback output skips the guard entirely on the live path.** The fallback chain includes `meta-llama/llama-3.3-70b-instruct:free` and `openrouter/free`.
- **Why it matters (patient safety):** The free-tier models are the ones most likely to produce unsafe medical content (less aligned, more prompt-injection-vulnerable), and they are the ones with zero server-side safety filtering. **This inverts the safety priority.**
- **Fix:** Run `guardResponse` on `fullContent` for every model before the stream closes, regardless of `servedModel`. If blocked, send a refusal chunk and close. Consider caching guarded fallback output too (the guard makes it safe).
- **Confidence:** 0.93 · **NEW.**

## Medium (18)

### M1 — `herb_ratings` UPDATE policy lets any authenticated user modify guest-owned ratings

- **Location:** `supabase/migrations/00045_rls_with_check_hardening.sql:21-25` (pending PR #44)
- **Evidence:** The guest branch `(user_id IS NULL AND guest_id IS NOT NULL)` does **not** bind `guest_id` to the caller — it matches _any_ guest-owned row. Any logged-in user can `UPDATE` any guest’s `rating` value / `experience` text.
- **Fix:** Drop the guest branch from the UPDATE policy: `USING (auth.uid() = user_id) WITH CHECK (auth.uid() = user_id)`. Guests can still INSERT; their rows become immutable. (RLS cannot enforce guest ownership — the anon role has no `auth.uid()`.)
- **Confidence:** 0.85

### M2 — Guest chat IDOR: client-supplied `guestId` trusted by SECURITY DEFINER RPCs

- **Location:** `src/lib/actions/chat-persist.ts:31,67,93,143,180` (all functions take `guestId` as a client parameter)
- **Evidence:** `guestId` is a function parameter, not re-derived from the HttpOnly cookie. The garden route correctly rejects body-supplied `guestId` and derives it server-side (`src/app/api/garden/route.ts:21-23,95`) — **chat-persist does not follow the same pattern.** A malicious client can invoke these server actions with any UUID and read/write that guest’s sessions/messages.
- **Why it matters:** Guest IDs are `crypto.randomUUID()` (unguessable), so practical exploitation requires the UUID to leak via another channel. Defense-in-depth gap. The DB-side `get_guest_chat_messages` was hardened in 00046 to require `p_guest_id`, but the _app_ still passes the client value rather than deriving it server-side — so the IDOR is closed only if the client value happens to match the cookie.
- **Fix:** In every `chat-persist.ts` function, ignore the client `guestId` argument, call `readGuestId()`/`getGuestId()` server-side, compare, and reject on mismatch. Drop the parameter from the public signature.
- **Confidence:** 0.85

### M3 — Open-redirect bypass in `safeReturnTo` via backslash-prefixed paths

- **Location:** `src/lib/actions/auth.ts:15-19`
- **Evidence:** `if (raw && raw.startsWith("/") && !raw.startsWith("//")) return raw;` blocks `//evil.com` but not `/\evil.com` or `/\\evil.com`, which normalize to `//` (protocol-relative) on several browsers. A crafted `?returnTo=/\evil.com` login link lands the user on the attacker site post-login.
- **Fix:** Use the URL API: `const u = new URL(raw, requestBase); if (u.origin === expectedOrigin) return u.pathname + u.search;` — or restrict to a regex and reject any `\`.
- **Confidence:** 0.6

### M4 — `profile.ts` mutating actions accept unvalidated client objects (PK/field injection)

- **Location:** `src/lib/actions/profile.ts:39-55` (`savePatientProfile`), `239-258` (`addMedication`), `290-307` (`saveDosageCalculation`), `175-205` (`saveHealthProfile`)
- **Evidence:** `savePatientProfile(profile: Omit<...>)` — the TS type omits `id` but **at runtime there is no Zod validation and no field stripping.** The insert is `{ ...profile, user_id: user.id }`; a client invoking the action with `{ id: "chosen-uuid", ...realFields }` sends `id` through and PostgREST inserts the caller-chosen primary key. `updatePatientProfile` correctly strips `id/user_id/created_at/updated_at` (line 101-107) — `savePatientProfile` does not. `addMedication` and `saveDosageCalculation` have the same unchecked-spread pattern.
- **Fix:** Add a Zod schema per action that whitelists exactly the allowed fields and strips the rest. Reject any payload containing `id`/`user_id`/`created_at`/`updated_at`.
- **Confidence:** 0.75

### M5 — Interaction name matching: bidirectional `.includes()` produces false negatives and false positives

- **Location:** `src/lib/actions/profile.ts:431-436`
- **Evidence:** `return userMedNames.some((mn) => ixName.includes(mn) || mn.includes(ixName));`. Seed `drug_name` values are `"Generic (Brand)"`. A user entering `"birth control pills"` against `"Oral Contraceptives"` → no substring → no match → no warning (the dangerous direction). `"na"` matches any drug containing “na” (false positives eroding trust).
- **Why it matters (patient safety):** A missed interaction warning is the worst failure mode — the user is actively taking a contraindicated drug and the app silently green-lights the herb.
- **Fix:** Normalize both sides against RxNorm/RxCUI — `user_medications.rxcui` already exists but is always inserted `null` by `addMedication`. Resolve to RxCUI on entry (an RxNorm client already exists in `src/lib/utils/`). As a fallback, match on a curated synonym map; at minimum tokenize and require full-token match rather than substring. (Moot until H1 is wired up, but must be fixed before wiring.)
- **Confidence:** 0.8

### M6 — Dose formula strings hardcode `"mg"` regardless of the selected unit

- **Location:** `src/lib/utils/dosage-calculations.ts:45,61,83,99`; overwritten unit at `src/components/calculator/dose-calculator-form.tsx:176`
- **Evidence:** Every formula returns `formula: "... x ${adultDoseMg} mg"` and `unit: "mg"`. The form overwrites `calcResult.unit = doseUnit` so the **displayed result** unit is correct, but the **formula text and explanation** still say “mg” when the user selected `g`/`ml`/`drops`. Example: adult dose `2 g`, Clark’s rule, 30 kg child → result `0.9 g` (correct), but the formula card renders `(30 kg / 68) x 2 mg`.
- **Why it matters (patient safety):** The formula string is the audit trail a clinician/user checks to verify the math. Showing “2 mg” when the input was 2 g could lead a user to re-scale into mg in their head → **1000× overdose.** Display/trust defect, not a calculation defect (the numeric clamp is unaffected).
- **Fix:** Pass the unit string into each formula function (or append the unit in the form when building the `formula`/`explanation` strings). Replace the hardcoded `" mg"` in the four formula functions with the supplied unit.
- **Confidence:** 0.9

### M7 — `checkout.session.expired` is mapped to `pending`, not `expired` (dead status branch)

- **Location:** `src/app/api/webhooks/stripe/route.ts:42-47, 315-319`
- **Evidence:** The mapper derives status from `session.payment_status`, which for Checkout Sessions is `paid`/`unpaid`/`no_payment_required` — **“expired” is not a value the session object carries.** Expired sessions report `unpaid` → persisted as `pending` forever. The `expired` enum added in 00026/00040 is unreachable.
- **Fix:** Special-case the event type: `case "checkout.session.expired": upsertDonation(session, "expired")`.
- **Confidence:** 0.7

### M8 — `unstable_cache` tags on herb detail are never invalidated via `revalidateTag` — admin edits cause cross-reference staleness up to 24h

- **Location:** `src/lib/actions/admin-herbs.ts:123-125,159-162` (writer) and `src/app/(main)/herbs/[slug]/page.tsx:74,183,225,270,333` (reader)
- **Evidence:** The herb detail page wraps every Supabase fetch in `unstable_cache` with distinct tags (`herb-meta-<slug>`, `herb-<slug>`, `monograph-<slug>`, `herb-faqs-<slug>`, `related-herbs-<slug>`) and `revalidate: 86400`. The admin writer only calls `revalidatePath` for the edited slug — **never `revalidateTag`**. The `related-herbs-<Y>` cache entry rendered on herb **Y**’s page lists herb **X**’s name; editing X never invalidates it. After an admin renames/republishes X, every other herb page showing X in “Related herbs” displays the stale name until its own 24h TTL expires. Compare pages (`revalidate: 3600`) are not path-revalidated at all on edit.
- **Fix:** In `createHerb`/`updateHerb`, add `revalidateTag("herb-" + slug)` etc. for the edited slug, plus revalidate compare/symptoms paths. For name/publish changes, bust every `related-herbs-*` tag (or `revalidatePath("/herbs", { type: "layout" })`).
- **Confidence:** 0.6

### M9 — Locale mismatch: verified context and system prompt use different locale sources

- **Location:** `src/app/api/chat/route.ts:210-215` vs `src/lib/ai/context-fetcher.ts:540`
- **Evidence:** `fetchVerifiedContext` does NOT accept a locale param; internally it calls `getLocaleFromRequest()` (reads `x-locale` header). The chat route reads `locale` from the JSON body (`parsed.data.locale`, line 188) and passes it to `getSystemPrompt`. So DB-injected herb/interaction data is localized per the **request header**, while the prompt’s `languageInstruction` is per the **request body**. A client on `/en` sending `{"locale":"fr"}` gets English DB data inside a French-instructed prompt.
- **Fix:** Pass the body `locale` into `fetchVerifiedContext` and use it for both DB localization and the system prompt.
- **Confidence:** 0.9

### M10 — Homepage has no canonical URL or hreflang alternates

- **Location:** `src/app/layout.tsx:31-85` (root `generateMetadata`) and `src/app/(marketing)/page.tsx` (no `generateMetadata`)
- **Evidence:** The root `generateMetadata` sets `metadataBase`, `title`, `description`, OG, twitter, robots — but no `alternates`. The homepage inherits the root metadata and has no `buildPageMetadata` call, unlike every other marketing/main page. `/` and `/fr/` (highest-traffic) lack canonical/hreflang.
- **Fix:** Add a `generateMetadata` to `(marketing)/page.tsx` calling `buildPageMetadata({ path: "/" })`, or add an `alternates` block to the root metadata via `buildAlternateUrls("/", BASE_URL)`.
- **Confidence:** 0.9

### M11 — RxNorm client swallows ALL errors; route’s Sentry-capture branch is dead code

- **Location:** `src/lib/utils/rxnorm-client.ts:36-38,56-58,75-77` and `src/app/api/rxnorm/route.ts:52-72`
- **Evidence:** `searchDrugs`/`getDrugByRxcui`/`getDrugInteractions` all `catch { return [] }`/`return null` with no logging/rethrow. The route’s `catch` distinguishes transient vs non-transient errors and calls `captureException` for non-transient — but because the client never throws, that branch only fires for errors from `rateLimit`/`NextResponse.json` (essentially never). Real RxNorm bugs are silently swallowed; users get empty results with no telemetry.
- **Fix:** In the client, distinguish transient (network/timeout) from non-transient (non-2xx ≠ 404, JSON parse failure) and `throw` on non-transient so the route’s `captureException` actually fires. At minimum `logger.error` inside the catch.
- **Confidence:** 0.85

### M12 — `interpret-search` OpenAI call has no timeout

- **Location:** `src/app/api/interpret-search/route.ts:48-67`
- **Evidence:** `openai.chat.completions.create({ stream:false, ... })` with no `signal`/`AbortController`. The chat route uses `AbortSignal.timeout(20000)`; this route uses the SDK directly with no timeout. A hung OpenRouter response stalls the serverless invocation until the platform default timeout.
- **Fix:** Pass `signal: AbortSignal.timeout(8000)`; fall through to the existing `[trimmed.toLowerCase()]` fallback on `AbortError`.
- **Confidence:** 0.9

### M13 — Cache write is fire-and-forget after stream close; may be dropped when the serverless invocation freezes

- **Location:** `src/app/api/chat/route.ts:373-374,388-389,38-64`
- **Evidence:** `persistToCache(...)` is called from inside the `ReadableStream` `pump()` callback after `controller.close()`, as a floating promise with no `await`/`waitUntil`/`after()`. Once the stream closes, Vercel can freeze/kill the invocation before the DB insert resolves.
- **Fix:** Use `after(() => persistToCache(...))` (from `next/server`) so the runtime keeps the invocation alive for it, or `await` the insert before `controller.close()`.
- **Confidence:** 0.8

### M14 — ILIKE wildcard injection in context-fetcher (user words not escaped)

- **Location:** `src/lib/ai/context-fetcher.ts:136-144` (`extractHerbNames`), `439-449` (`batchLookupHerbs`), `371-373` (`lookupInteractions`)
- **Evidence:** User words are interpolated into `name.ilike.%${w}%` with no `escapeForIlike`. A user message containing `%` matches every row. The `escapeForIlike` helper exists and is correctly used in `/api/herbs/search` (line 44) — but not here.
- **Fix:** Run every user-supplied value bound for an ILIKE filter through `escapeForIlike` in `extractHerbNames`, `batchLookupHerbs`, `lookupInteractions`, and `lookupHerb`.
- **Confidence:** 0.85

### M15 — Chat session persistence drops user messages (debounce race)

- **Location:** `src/components/pharmacist/chat-interface.tsx:190-238`
- **Evidence:** The persistence `useEffect` depends on `[messages.length]` and debounces 1500ms, clearing the prior timer on each length change. When `sessionIdState` exists, `save` persists only `messages[messages.length - 1]`. A user send then assistant reply within 1500ms (the common case) → the length-3 timer is cleared before firing; the length-4 timer fires and saves only the assistant message. **The user message is never persisted.**
- **Fix:** Track a `lastSavedIndex` ref; in `save`, iterate from `lastSavedIndex` to `messages.length - 1` and call `addGuestMessage` for each. Remove the single-message-only branch.
- **Confidence:** 0.8

### M16 — Chat `retryFailed` sends stale error message in history

- **Location:** `src/components/pharmacist/chat-interface.tsx:380-384` (and `sendMessage` at 267-273)
- **Evidence:** `retryFailed` does `setMessages(prev => prev.slice(0,-1))` then calls `sendMessage(messages[messages.length - 2]?.content ?? "")`. But `sendMessage` builds the request body from its closure-captured `messages`, which still contains the error assistant message. The retried request includes the error text as assistant history and duplicates the user message.
- **Fix:** Have `sendMessage` read the latest messages via a ref (`messagesRef.current`) or accept a `historyOverride`; `retryFailed` passes the sliced array.
- **Confidence:** 0.75

### M17 — ThemeToggle + UnifiedNavbar mobileTheme hydration mismatch + DOM mutation during render

- **Location:** `src/components/theme/theme-toggle.tsx:38-44`; `src/components/layout/unified-navbar.tsx:70-73`
- **Evidence:** `useState(() => { if (typeof window === "undefined") return "system"; ... return localStorage value })` → server renders `system` (icon `Monitor`), client may render `dark` (icon `Moon`). `applyTheme()` also mutates `document.documentElement` during render (unsafe under React 19 StrictMode).
- **Fix:** Initialize state to `"system"` unconditionally. Read localStorage and call `applyTheme` in a `useEffect` after mount. Use a `mounted` gate or `suppressHydrationWarning` on the icon span.
- **Confidence:** 0.8

### M18 — Sitemap `lastModified` bumps hourly despite a “stable date” comment

- **Location:** `src/app/sitemap.ts:12`
- **Evidence:** `const STATIC_PAGE_MODIFIED = new Date();` at module top with comment L10-12 claiming a stable date prevents hourly churn; but `revalidate = 3600` re-evaluates the module hourly → fresh timestamp each revalidation. Every static page reports a new `lastModified` ~hourly. Google re-crawls wastefully.
- **Fix:** `const STATIC_PAGE_MODIFIED = new Date("2026-06-22T00:00:00Z");` or derive from a build ID/commit SHA.
- **Confidence:** 0.85
